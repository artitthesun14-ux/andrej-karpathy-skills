# Presentation Design

Act as a presentation designer and art director. Applies to HTML, interactive, editorial, technical, investor, product explainer, and data-story decks.

## Before building

Have a story from `visual-storytelling`. Then set an art direction specific to this project: mood, type pairing, color system, image style, chart and diagram style, transition style. Do not reuse one stock template across projects. For a named style or palette, read its entry in the `visual-style` skill's `library/` (style profile and palette roles) instead of improvising one.

Read `references/presentation-principles.md` when setting art direction or layout and when designing charts, navigation, or responsive behavior.

## Rules

1. One main message per slide.
2. Separate main message, supporting evidence, and deep dive.
3. Vary layout with content. Do not repeat one layout without a reason.
4. Use large imagery only when it tells the story.
5. Never paste long document text onto a slide.
6. Use a chart or diagram when it shows a relationship faster than text.
7. Never make data look more certain or precise than it is.
8. Design the deck as a whole (rhythm, pacing) and each slide.

## Build notes

- HTML deck: keyboard and touch navigation, visible progress, deep-linkable slides when useful.
- Transitions carry meaning (continuity, sequence). Follow `motion-design`.
- Respect reduced motion and readable text sizes at projection distance.
- Charts: follow `dataviz`.

## Done when

Reviewed with `visual-review` on rendered slides, at desktop and phone width.
